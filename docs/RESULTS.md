# 버스 노선 인식 평가

2026-09-29 기준 개발용 영상 평가 결과입니다. 버스 검출·문자 영역 검출·OCR·목표 노선 판정을 연결한 파이프라인을 전체 영상에서 실행했습니다.

| 조건 | 목표 노선을 인식한 영상 |
|---|---:|
| 이전 단일 관측 포함 기준선 | 105/143 (73.4%) |
| 번호판·전화번호 필터 적용, 원본 재추론 | 106/143 (74.1%) |
| 같은 코드로 원래 속도 재생 | 106/143 (74.1%) |

분모는 활성 dataset1 79개와 dataset2 64개입니다. 영상 한 개를 한 건으로 셉니다. 정답은 사용자가 지정한 `target_route`로 시뮬레이션했고, 버스 도착 API는 연결하지 않았습니다. 같은 차량·비슷한 장면이 여러 영상에 있으며 이 자료는 개발 중 이미 검토했습니다. **74.1%는 목표 번호가 한 번 이상 인식된 영상의 비율**입니다. 모든 출력의 정답 비율이나 독립 데이터 일반화 성능이 아닙니다.

번호판 의심 영역에 위치·색상·밝기 검사를 적용하고, 작은 4자리 숫자는 좌우 문맥에서 전화번호 일부인지 확인합니다. 확인된 `7284·1577·9350`은 원시 OCR에 남아도 노선 근거로 인정하지 않았습니다. 정상 측면 PRINT·LED의 기존 인식 근거를 보호했고, 실제 7017 영상에 목표 7016을 넣은 별도 반례도 인식하지 않았습니다.

새로 인식한 영상은 측면 PRINT `660` 한 개입니다. 기존에도 OCR은 정확했으나 후보가 너무 많아 판정을 보류하던 영상으로, 필터 적용 후 적격 후보가 26개에서 11개로 줄었습니다. 기존 성공 영상의 감소는 없었습니다. 별도로 시험한 다른 목표 중 새로 통과한 `10/마포10`과 `20`은 한글 오독입니다. 세 조합은 실제 두 장면이므로 목표 인식률 증가를 전체 판정 정확도 개선으로 해석할 수 없습니다. 광고 연도, 일반 차량 표기, 손상 LED와 부분 번호 오독도 남아 있습니다.

RTX 5080 Laptop GPU에서 영상 전체를 5fps로 원래 속도 재생한 결과, 4,938프레임을 처리했습니다. 프레임 처리 p95는 160.32ms, 프레임 나이 p95는 164.07ms, 최대는 439.48ms였습니다. 샘플 3개를 폐기했고 29프레임은 나이 300ms를 넘었습니다. 휴대폰 전송·추론·음성 안내 시간은 포함하지 않습니다.

소스와 단위·통합 테스트는 Git에 포함됩니다. 원본 영상, 평가 CSV와 프레임별 로그, crop 검토 페이지는 저장소의 Git 제외 경로 `data/`, `output/`, `workbench/`에 로컬 보존합니다. 상세 근거의 로컬 시작 페이지는 `workbench/index.html`이며, 최종 실험 로그는 `output/plate_filter_20260929_run01/`에 있습니다. 모델 가중치도 `.cache/`에 로컬 캐시합니다. 로컬 테스트 35개가 통과했습니다.
