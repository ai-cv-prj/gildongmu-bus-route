- 학습 데이터는 수동 주변 창이며 제품 입력인 자동 버스 영역과 다릅니다. 국소 시험 25개 주 번호 중 YOLO+PARSeq 23개 일치, CRAFT+PARSeq 15개. 완전 중복 M6628을 빼면 22/24, 15/24.

## 재현 순서

프로젝트 루트, 기존 `.venv`, `PYTHONPATH=core`를 사용합니다. GPU 단계는 같은 GPU에서 순차 실행합니다. 기존 출력 디렉터리를 지우거나 덮어쓰지 마세요. 재실행은 스크립트를 새 run ID로 복사하고 모든 `O`/`OUT`/`W` 경로를 새 디렉터리로 바꿉니다. 기본 경로의 원래 결과는 보존해야 합니다.

1. `prepare.py`: 이전 보고서 crop·현재 기준선으로 원본 프레임/검수 제안을 수집합니다. 제안은 정답 라벨이 아닙니다. JPEG는 문맥 검수/학습용이고, 수동 OCR crop은 다음 단계에서 원본에서 다시 PNG로 추출합니다.
2. `review_manual_draft.py`, `freeze_manual_labels.py`: 사람이 볼 수 있는 원본 문맥과 확대 crop을 대조해 확정한 수동 좌표를 기록합니다. 코드의 영상 번호별 좌표는 **평가 라벨**이며 제품 추론 예외가 아닙니다. 새 데이터는 다시 시각 검수해야 합니다.
3. `diagnose.py`: 고정 수동 좌표의 원본 PNG exact/pad10/수동 quad 보정 PARSeq 진단. 모델에 정답 문자열을 전달하지 않습니다.
4. `build_dataset.py`, `finalize_dataset.py`: 현재 정상 번호와 수동 실패 번호, 검수된 비노선 음성으로 국소 주변 창을 만듭니다. 2차 문맥 검수에서 보이는 추가 노선 표시 4개를 라벨링합니다. v64의 상단 잘림도 수정합니다. 초안 데이터셋은 보존합니다.
5. `correct_region.py`: v64의 2차 검수 좌표를 원본 PNG로 추출합니다. 수정 전 수동 OCR은 보존합니다.
6. `train.py`: `protocol.json` 조건으로 YOLO11n을 60 epoch 학습합니다. 검증 mAP50–95로 best checkpoint를 고릅니다. 분할은 촬영일 기준이며 같은 영상/동일 이미지 해시가 서로 다른 split에 없음을 검사합니다.
7. `evaluate.py`: 고정 confidence=0.25, IoU=0.5로 시험 국소 창과 자동 버스 ROI를 평가합니다. 후자는 이전 전체 영상 추적 로그의 모든 자동 bus_box를 사용하며, 수동 번호 좌표는 채점에만 씁니다. v64 보정 OCR도 기록합니다.
8. `report.py`: 진단 JSON/CSV와 이미지 HTML을 만듭니다. 원시 결과·초기 라벨·2차 교정을 모두 보존합니다.

`output/route_detector_20260930_run01/` 아래에 프로토콜·라벨·출처·학습 로그·가중치·OCR 출력·박스·시간·검사 결과가 있습니다. `artifact_validation.json`은 링크, 이미지, 분할, 제품 코드 해시와 집계를 검증합니다.

## 해석상 제한

- 단일 검수자(Codex)의 시각 검수이며 라벨 일부는 불확실성을 표시했습니다. 사용자 CSV 정답은 수정하지 않았습니다.
- 시험 양성 25장 중 남은 실패 영상은 M7731·602 두 장뿐입니다. 33개 전체의 독립 성능으로 해석할 수 없습니다.
- 같은 날짜의 유사 영상은 같은 split이지만 다른 날에도 같은 노선·정류장·차량이 반복됩니다. 새 촬영 데이터의 독립 검증은 없습니다.
- 음성 시험은 광고·번호판 두 창뿐입니다. 검출기만으로 등록번호와 광고 제외가 해결됐다고 주장하지 않습니다.
- 정확 문자열 점수와 박스 지표는 최종 버스 귀속·추적·경쟁 후보·최신성 판정을 포함하지 않습니다. 영상 인식률, 새 최종 오인식, 실시간 전체 지연으로 환산하지 않습니다.
- 제품 통합 전 실제 자동 버스 영역의 모든 노선 표시와 충분한 음성 라벨이 필요합니다. 통합 후 전체 143개와 7017→7016 반례의 offline/realtime 재검증이 필요합니다.
