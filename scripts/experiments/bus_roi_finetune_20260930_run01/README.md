# 버스 전체 영역 검출기 fine-tuning

기존 `route_detector_20260930_run01`의 단일 노선 표시 검출기를 실제 자동 버스 ROI에 맞춰 추가 학습합니다. 번호 문자열을 학습 클래스나 추론 입력에 사용하지 않습니다. 번호판·광고·차체 숫자는 노선 표시 클래스의 배경이며 기존 제품 제외 필터는 변경하지 않습니다.

## 재현

프로젝트 루트에서 `PYTHONPATH=core .venv/bin/python <script>`를 사용합니다. 기존 출력 디렉터리를 지우거나 덮어쓰지 마세요. 재실행할 때 새 run ID로 모든 출력 경로를 변경해야 합니다. GPU 단계는 순서대로 실행합니다.

1. `prepare.py`: 이전 시각 검수 원본 프레임과 원본 파이프라인의 자동 bus_box를 결합합니다. 전체 번호의 98% 이상을 포함하는 자동 박스가 없는 3개는 별도 기록합니다. 초안은 학습용 정답이 아닙니다.
2. `labels.py`: 전체 버스 문맥을 눈으로 확인하고 추가 표시를 라벨링합니다. 여기의 영상별 좌표는 수동 평가/학습 라벨이며 추론 예외가 아닙니다. 추가 영역은 확대 crop으로 다시 확인합니다.
3. `freeze.py`: 2차 검수로 잘못된 제안을 제거/수정합니다. `dataset_reviewed`를 새로 만들고 기존 초안은 보존합니다. 날짜별 분할, 교차 split 영상/이미지 중복 검사를 합니다. 학습에 보이는 번호판·광고·차체 숫자는 배경 음성이고, 별도 검수 음성 crop도 함께 사용합니다.
4. `train.py`: 이전 전용 YOLO11n 가중치에서 전체 층을 미세조정합니다. 100 epoch, imgsz=960, batch=8, AdamW lr=0.0003, freeze=0, seed=20260930, flip 없음. 검증 mAP50–95로 best 선택. 조건은 `protocol.json`에 시험 평가 전 저장합니다.
5. `evaluate.py`: 촬영일 분리 시험 25개 원본 프레임의 **모든 자동 bus_box**에서 이전 모델과 새 모델을 각각 640/960으로 실행합니다. 같은 해상도 비교로 학습 효과와 해상도 효과를 분리합니다. 수동 GT는 채점에만 사용합니다. 별도 음성 crop 10개의 결과는 학습/검증/시험 출처를 함께 기록합니다.

## 평가 해석

- 이 시험은 이전 예비 실험에서 이미 살펴본 개발용 holdout 날짜입니다. 새로 수집한 독립 평가 데이터가 아닙니다.
- 시험 양성 25장에는 완전 중복 M6628 두 장이 있습니다. 서로 다른 split으로 분리하지 않았습니다.
- 박스 IoU≥0.5를 만족하는 주 번호 crop의 OCR 정확 문자열을 셉니다. 전체 번호 95% 포함, 고신뢰도(문자/EOS 최소 0.98)도 별도 집계합니다.
- 학습 영상의 성공률을 전체 영상 일반화 성능으로 주장하지 않습니다. 기존 143개 전체 영상 실측 110/143과 정지 프레임 평가를 합산하지 않습니다.
- 기존 정상 PRINT·LED 및 음성 반례의 손실을 확인해야 제품 교체를 판단할 수 있습니다. 제품 추론에 통합한다면 전체 143개와 7017→7016 반례를 원본에서 offline 다음 realtime으로 재검증해야 합니다.

## 전체 원본 영상 검증

`run_videos.py`는 제품 파일을 수정하지 않고 실험용 `RouteDetector`를 기존 `analyze()`에 주입합니다. 번호 영역 검출만 전용 YOLO로 바꾸고, 기존 버스 검출/ByteTrack, PARSeq, 번호판·전화번호·경계·귀속·문자 밀도 필터, 전체 영역 재확인, 경쟁 번호/단일 관측/최신성 정책은 재사용합니다. 목표/파일명별 예외는 없습니다. 입력 목록은 기존 143개+7017→7016 반례와 바이트 단위로 같습니다.

- `PYTHONPATH=core .venv/bin/python scripts/experiments/bus_roi_finetune_20260930_run01/run_videos.py`: 단일 GPU에서 offline 후 realtime 순서. 새로운 출력 경로만 허용합니다.
- `compare_videos.py offline`, `compare_videos.py realtime`: 기존 110/143 기준선 대비 증가·감소·다른 목표의 새 통과·번호판/광고·지연 비교.
- `video_evidence.py`: 실행 종료 후 원본 RGB에서 증가·감소·새 통과의 crop/문맥 이미지 추출. realtime 측정과 무거운 원본 디코딩을 동시에 수행하지 않습니다.

원시 로그 호환을 위해 `craft_ms` 열에는 새 전용 검출기 시간이 기록됩니다. `upper` search_zone은 이 실험에서는 버스 전체입니다. 별도 body 탐색은 빈 결과이며 CRAFT를 실행하지 않습니다. 설정 JSON에도 이 차이를 명시합니다. 제품 기본 실행 경로는 바꾸지 않았습니다.

## 완료 결과와 후처리

전체 offline/realtime 모두122/143, 기존110 대비 새성공13·손실1. 학습 촬영일75→87/97, 검증12→12/19, 시험23→23/27. 새 오류17조합(16장면), 실제 다른 버스5조합. 정상273 손실과 새 오류 때문에 기본 제품은 교체하지 않았습니다. realtime 처리p95 94.38ms·나이p95 96.52ms·폐기0. 원본과 이전 결과 보존.

증거 contact sheet와 필요한 인접 시점을 사람이 검토한 뒤 `review_evidence.py`로 판독 기록을 저장했습니다. `summarize.py`, `report.py`, `validate.py` 순서로 최종 집계·로컬 보고서·무결성 검증을 생성합니다. 인접 시점 추가 이미지는 `video_evidence/supplement/`에 보존했습니다. 원본2.0초의7011이2.4초에는 LED 마지막 자리 발광이 빠져701로 보이므로 공간 확장만으로 해결할 수 없는 오류도 포함됩니다.

학습용 bus crop은 이전 보존 프레임 JPEG에서 PNG로 추출했습니다. 전체 영상 평가와 최종 판독 근거는 원본 파일을 다시 디코딩했습니다.
